## How This File Works

PROJECTS.md is a living document. Agents update it as projects
evolve. Each project entry tracks status, connections to other
projects, and the link back to GOALS.md.

When an agent working on one project discovers something relevant
to another project, it updates the cross-references here. This is
how the system maintains free association across domains — the
consilience principle applied to project management.

**Security:** Projects are open to cross-project review by default.
If a project requires restriction (client confidentiality, sensitive
IP, etc.), mark it as `access: restricted` and agents working in
other contexts will not access its episodic memory.

**Governance:** PROJECTS.md follows tactical tier rules — agents
have full autonomy for additive updates (new projects, status
changes, cross-references). Removing a project or changing its
goal alignment requires Jake's approval.
